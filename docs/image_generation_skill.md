# 图片默认 Skill 与风格案例

每次网站图片任务默认应用 `skills/image-generation-default/SKILL.md`，可选风格来自同目录 `styles.json`。无模板时保留用户自己的风格；选模板时仅加入视觉表达，不把预览图作为输入或复制案例主体。

## 用户操作

图片工作台的“视觉风格”可以快速选择模板，“浏览效果与案例”展示 8 种风格的原创生成预览与案例提示词。应用风格保留输入框原文；使用案例填入示例需求和比例并提供撤销；复制按钮只复制示例文字。原始需求、选中风格及最终发送的规则化提示词可在任务详情查看。

## 实现与边界

1. **归属**：Skill + 图片提示词编译器 + Frontend。编译器属于 `image_backend` 组，不持有存储、积分或 HTTP 依赖。
2. **依赖**：`WorkbenchState`、`TaskRunner` 和 `RemoteQueue` 使用编译器公开函数，HTTP 通过图片应用服务读取风格目录。新增前端组件通过回调访问需求输入，不访问其他组件或页面状态。
3. **复用**：仍用已有创建任务、提交确认、Worker、Backend、`StorageManager.register_output_*` 和积分事务。提示词整理由已有 Codex 图片执行轮次完成，不增加一次文本模型调用。
4. **数据兼容**：旧任务 JSON 不改动。新任务在现有 `.workbench/tasks/<project>/<task>.json` 附加 `image_prompt` 快照：原始需求、风格 ID、规则版本/摘要、结构化规格与编译文本。保存请求指纹仅在选风格时增加该字段，旧的无风格请求仍可重放。
5. **Core**：不改 StorageManager 或 Task 数据模型。TaskRunner 只在调用 Backend 前用快照替换传出 Task 的 prompt；磁盘原始任务保持不变。远程队列使用同一文本放入原有 `task.prompt` 字段，旧执行器无需新增协议字段即可收到规则。
6. **行为**：未选择风格和编辑任务也应用默认规则；旧任务无快照时在执行边界套用当前 Skill。新任务保存快照，后续更新模板不会修改已保存需求。权限、参考解析、计费、幂等、恢复与产物归档继续由原服务负责；恢复产物不调用模型。
7. **验证**：单元覆盖规则载入、用户原文/精确文字、可选风格及无样例主体串入、编辑参考职责；服务/HTTP 覆盖快照、幂等、非法风格和旧任务长度边界；本地/远程 Mock 执行检查实际收到的提示词；浏览器检查预览资源、模板应用、案例撤销、保存及窄屏显示。功能迭代使用 `scripts/verify.py --module images`，执行边界变更完成后使用完整 `scripts/verify.py`。
8. **回滚**：回退代码和本次静态资源即可，无业务数据迁移。附加快照可由旧版本忽略，原始 task.prompt 保持可用；已排队远程任务持有的提示词不会在断线时重发模型调用。

风格目录和 Skill 为应用随包资源，运行时不联网下载模板。预览图是可公开的项目样例；用户图片、提示词和 Workspace 记录不加入风格库。研究来源与原创处理见 [sources.md](../skills/image-generation-default/references/sources.md)。
