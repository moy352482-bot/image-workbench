# 管理中心

管理员登录后，从工作台侧栏“管理中心”进入 `/admin`。普通账号看不到入口，直接请求页面和管理 API 也会被拒绝。使用现有账号会话、同源检查和 CSRF；没有新增默认管理员密码或独立登录系统。

## 页面与操作

- **运行概览**：源码/发布版本、服务启动时间、执行器状态、队列、账号与工作空间数量，以及最近检查和维护记录。待处理名额只统计仍冻结或执行中的预约。
- **版本与部署**：“准备更新包”实际运行 Python 功能回归和网页 JavaScript 语法检查，通过后保存固定发布包。“预览并部署”展示目标与版本；管理员确认后，后台使用现有 SSH 发布和健康检查流程。
- **功能测试报告**：保存通过、失败、跳过、耗时和失败用例名称，展开查看检查分项。报告对应运行代码、测试和部署脚本的指纹；代码变化后提示重新检查。缺少 Node.js、没有发现测试或检查中代码变化均不能生成可部署包。
- **运行配置**：只读展示注册准入、赠送积分、生成价格、等待任务上限与每日提交预算，不直接修改用户权限、钱包或服务配置。

后台操作有持久编号与状态，页面可关闭后重新查看。检查、准备和部署不能重复并发提交；任务在独立维护进程中运行，网页重启不会主动重放动作。管理接口只接收固定操作和受控标识，不接受 shell 命令、测试路径、SSH 主机或密钥内容。

## 发布边界

部署目标来自管理进程所在主机的 `deploy/server.json`，私钥仍由现有本机文件/SSH agent 管理。网页不读取或展示私钥内容，也不提供修改 SSH 配置的输入框。首次连接的主机指纹仍按 [部署说明](one_click_deploy.md)核实；网页发布不会关闭严格主机校验。

准备成功后，报告、程序包、manifest 和发布脚本保存为同一版本。确认有效期为 5 分钟，仅当前管理员会话可使用一次。提交前与执行前再次检查代码、包及目标配置；变化则要求重新准备或预览。上传和远端检查始终使用批准的文件摘要，不接受修改后的包或脚本。

发布会重启目标网站。现有自动回退仅涉及程序，不能撤销业务数据写入；首次发布没有旧版可回退。SSH 断线或执行超时会显示“需核实”，不能据此断言已经发布、未发布或成功回退。上传最多等待 10 分钟，远程安装及启动最多等待 30 分钟，超过后不会自动重试。

本机源码管理端具备检查和准备能力；服务器发布目录仅包含运行程序，不包含测试、发布工具和本机 SSH 密钥，所以相应按钮显示不可用原因。云端管理页面仍可查看服务与配置。这样无需给线上服务增加系统管理权限。

## 中断与恢复

维护进程定期写心跳。长时间未更新，或远端发布没有可确认结果时，页面显示“需核实”并停止接受新维护动作。先检查维护进程是否已经退出；涉及发布时核对目标服务器当前版本和服务状态。

在维护记录详情中勾选已核实声明，再选择“结束待核实记录”。服务端同时检查执行锁已经释放。这个动作只记录管理员核实，不会重跑任务、重传程序或把未知结果改写成部署成功。

报告和操作记录保存在当前数据根的 `.workbench/admin/`。原始维护日志留在本机，网页只显示受控摘要和失败用例名；没有任意路径下载接口。发布包仍在源码目录 `.deploy/`，已排除在 Git 之外；不自动清理历史版本或备份。

界面借鉴 [Coolify、Dokploy、Portainer 的部署历史与权限模式](admin-design-references.md)，没有引入整套平台或复制第三方实现。
