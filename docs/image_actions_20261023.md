# 图片工作台直接生成、批量提交与错误说明

## 行为

- 新建任务左侧并排放置“保存任务”和“直接生成”。保存只创建草稿，不调用模型、不冻结积分；
  直接生成先沿用原保存接口，再以明确生成确认提交同一任务。双击只产生一次保存和提交。
- 保存成功后自动勾选该草稿，可以继续保存不同需求。历史列表支持逐项勾选和全选待生成，
  展示数量与服务端报价合计。“批量生成”只提交选中的可生成草稿，按保存时间进入现有队列。
- 批量前刷新服务端任务状态和账户余额；总积分不足时不开始提交。期间某项提交失败即暂停，
  展示已确认提交数量，刷新真实状态，保留尚未提交的选择。已受理任务不重复提交或自动重试。
  API 最终仍逐项校验权限、额度与幂等，前端估算不代替服务端事务。
- 列表在队列仍有活动任务时持续刷新全部任务状态。切换子项目清空批量选择；请求使用提交时的
  Workspace，不因切换页面把任务投到其他空间。提交已完成后关闭页面不影响原持久队列执行。
- 保存后生成提交失败时保留已保存任务，用户从历史继续处理，无需重新保存一份。
- 任务列表采用最新请求结果；首次加载的旧响应不能覆盖刚保存的任务或其恢复操作。
- 失败任务可“修改需求后新建”：加载原始需求、风格、比例、基底图和参考图，不覆盖原任务。

## 图片 Skill 与参数

预设 `image-generation-default`、视觉风格、宽高比、生成/编辑类型、参考图和基底图仍沿用
原任务选项与快照。单次、直接生成和批量均通过同一接口创建和执行任务，Provider 接收编译后的
Skill 提示词及显式比例。API 显式比例为 1:1 → 1024×1024，3:2 → 1536×1024，2:3 → 1024×1536；
自动不发送固定尺寸。没有新增提示词模型调用。

## 线上错误原因

错误代码 `content_policy_violation`。3:2 比例和 `retro-film` 风格已正确保存，接口使用
`gpt-image-2` 与 `1536x1024`；供应方没有说明具体触发内容。网站冻结的 40 积分已经退回。

新增 `image_api_content_rejected`，将这类上游拒绝与泛化服务错误分开，远程队列可传回该类型。
页面使用固定中文说明，不暴露供应方任意消息、Key 或日志。已结算历史任务保持原记录，
新增修改需求入口也适用于此前的泛化失败，避免更改已完成的回执或账本。
网站不能替供应方取消内容审核，不自动重复发送被拒绝的原请求，也不自动更改用户需求。

## 实现边界与验证

功能属于 Frontend，错误识别属于既有 Provider，任务查询仅补充派生字段 `can_generate` 到摘要。
复用任务保存/提交、`WorkbenchState`、`IdentityStore`、`RemoteQueue` 和原 Worker，不新增队列、
批量账本、数据模型或 Core 特例。HTTP 原路径、存储格式、积分和幂等规则不变；摘要字段是兼容性增加。
回滚仅需切换代码版本；已保存或受理任务继续使用原数据与队列，无数据迁移。

新增真实 Chromium + HTTP + 临时存储 + Mock API 测试覆盖直接生成参数、重复点击、连续保存、
选中子集、总积分不足、部分提交失败后继续、全部队列状态刷新、内容拒绝与退款、参数载入及手机布局。
API 专项覆盖上游拒绝分类、脱敏、远端回传与退款。验证不使用真实业务数据，不调用付费图片模型。
