# 网站优化与商业化准备方案

更新：2026-10-13。本文区分已实现能力、待开发内容和发布前决策；逐轮状态见 [循环优化清单](../work/iteration-plan.md)。

## 推进顺序

| 阶段 | 产品与工程工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 可靠的个人工作台 | 修复重试/积分一致性，明确环境与真实生成，完善失败/离线提示，量化列表性能 | 关键行为有复现与回归证据，原图和历史记录保持 |
| 小规模受控内测 | 可配置注册准入、赠送额度防滥用、每账号及全局配额、可审计运营记录、备份恢复 | 越权和并发用例通过，注册不能无限获取生成资源，恢复演练可核对 |
| 收费前验证 | 明确上游商用模式、单位成本、服务边界、客户条款及保留政策；设计套餐与退款规则 | 上游合同/成本/公开部署和支付方案由负责人确认；关键未知项已消除 |
| 付费产品 | 在前述决策后实现支付订单、可验证回调、幂等入账、对账和运营支持 | 支付沙箱、失败补偿和发布回滚通过，再单独批准上线 |

当前不开发支付、不自动充值、不改变既有 Codex 调用链。优先把内测准入与资源成本控制做好。复杂团队权限、企业协作、营销自动化不在当前清单。

## 产品内积分与真实成本

既定规则继续保留：普通新账号 200 积分，纯提示词每张 40，参考图/历史编辑每张 60；moy 无限额度。积分是产品计量，不等于人民币，也不表示上游额度无限。

冻结和结算采用提交时的价格快照。后续调整政策只能影响新提交；账单应展示实际冻结/结算数量，不能按新价重算历史。退款表示释放本产品积分；若上游失败也产生费用，该费用仍应计入运营成本。

建议用以下参数建立成本表，取得实际数据前不填写猜测价格：

| 参数 | 应采集的证据 |
| --- | --- |
| 单次成功成本 | 上游账单或经许可的额度/订阅成本分摊；不得用“本机调用免费”代替 |
| 失败及重试成本 | 每次执行 ID、失败类型、是否消耗上游额度、仅归档恢复与真实再生成的区别 |
| 存储与带宽成本 | 原图/结果总字节数、保留时长、下载流量、备份份数 |
| 运维成本 | 执行器可用率、平均与高分位耗时、排队时间、人工处理量 |
| 赠送成本 | 新账号赠送总量、已用赠送额度、重复注册和异常消耗 |
| 收入参数 | 经确认的套餐金额、包含积分、退款与税费、支付渠道成本 |

计算关系：单位交付成本 =（成功调用成本 + 失败/重试成本 + 存储/带宽 + 运维分摊）÷ 成功交付张数。套餐贡献 = 实收金额 − 套餐内预期交付成本 − 赠送/退款及支付成本。模型、尺寸、参考图和重试策略变化后需重新测算。

先按邀请内测评估需求与成本，决定是否采用包含固定积分的订阅或预付积分包。当前没有真实单次成本及转化数据，不给出虚构售价或毛利承诺。

## 防滥用与容量

认证限流只限制请求频率，不等于解决重复账号套取 200 积分。已实现显式 `open` / `invite` / `closed` 注册策略及普通账号总量上限，一次性邀请消费与赠送同事务提交；现有本机行为保持兼容，部署示例明确邀请模式。配置与签发步骤见 [受控注册](accounts_workspaces_credits.md#受控注册)。邀请码使用、初始赠送和任务执行有数据库记录，普通用户不能自改角色、余额和价格。

单执行器是当前实际容量边界。已增加显式可配置的每账号待处理数、全局待处理数与每日提交积分预算；预算拒绝返回 429、不冻结额度也不创建作业，已冻结任务仍按原策略结算。同一请求重放不重复占预算，结果待确认仍占队列名额。管理员无限产品积分也受运营预算限制。

| 运营配置 | 定义 | 默认 / 部署示例 |
| --- | --- | --- |
| `IMAGE_WORKBENCH_MAX_PENDING_PER_ACCOUNT` | 单账号冻结、执行中及结果待确认的任务数 | `0` 不限制 / `3` |
| `IMAGE_WORKBENCH_MAX_PENDING_TOTAL` | 全站上述待处理任务数 | `0` 不限制 / `30` |
| `IMAGE_WORKBENCH_MAX_DAILY_SUBMITTED_CREDIT` | UTC 当日新提交预约金额累计上限 | `0` 不限制 / `2000` |

每日预算是运营代理指标，不是真实货币费用上限；包括归档恢复的提交，退款不返还当日预算，因为上游失败也可能消耗资源。仅成功退款后释放待处理队列名额。配置错误拒绝启动，修改配置后重启服务生效。现有本机默认兼容，示例值为内测起点，须按实测容量调整。

邀请模式配合账号总量可界定初始赠送规模：例如示例最多 100 个普通账号，共最多赠送 20,000 积分，按最低 40 积分/张最多对应 500 次成功交付；这不包含失败重试成本，也不代表许可或收入预测。实际费用仍依赖上游成本证据和运营预算。

API 的账号/空间验证、队列幂等、原始图片保护和故障恢复是上线前要求。认证与授权方法参考 [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) 和 [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

## 上游与公开运营边界

当前复用个人 Codex 登录的技术链路已能工作，但这不等于已核实对外收费 SaaS 的适用授权。OpenAI 当前[个人服务条款](https://openai.com/policies/terms-of-use/)区分个人与企业/开发者服务，对账号及服务使用有约束。收费前需核对具体账号计划、上游合同、允许的集成方式、客户内容处理及可持续成本；确认后再决定是否另行接入适用于该模式的上游。这里是待核实条件，不能由代码测试代替。

公开部署还需要真实 HTTPS、反向代理的可信来源配置、密钥管理、隔离备份、恢复验证和运行监控。当前只完成本机及独立回环演练的部分，云实例和真实域名以实际探针为准，不使用文档记录宣称已上线。

## 数据与客户体验

图片与项目默认私有；账号停用应立即阻止旧会话。删除先进入回收站，永久删除和保留期限需按用户确定的产品政策实施。日志不能包含密码、会话令牌、启用凭据或原始敏感表单；客服/运营需要的任务状态不应顺便暴露其他用户的图片。

开始前展示预计积分；排队、执行、检查、成功扣除、失败退款分别可见。演练环境及固定测试图在登录与结果处明确标注。先用事实修正关键体验，再基于独立样本测量页面加载性能，避免为了速度削弱权限检查。

## 每轮交付要求

保存一个问题描述、修改前证据、最终行为、相关检查、已知边界及下一步。代码审查关注 SQL 与数据安全、并发、权限、模型输出信任边界、状态枚举和异常恢复。只在有新改动、失败或未解决风险时扩大检查，不以检查次数或主观评分替代验收。
