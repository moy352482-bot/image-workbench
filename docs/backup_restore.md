# 业务数据备份与隔离恢复

`scripts/backup_workbench.py` 备份完整数据根目录，验证清单和 SQLite 后恢复到一个全新的目录。它不连接服务器、不调用模型、不启动执行器，也不切换真实服务。备份使用 Python 标准库，可在本机 Windows 或服务器本地执行。

当前的 [代码发布工具](one_click_deploy.md) 只更新程序。程序回退不能撤销数据格式迁移；原有项目迁移备份也不包含完整图片集。这份工具用于补齐完整业务数据副本及恢复验证。

## 备份前提

先让当前任务正常结束，再停止对应数据根的网页服务、执行器和其他写入程序。结果待确认的生成任务应先人工核对；恢复后不能直接自动提交或重跑队列。工具要求显式传入 `--writers-stopped`，不会代替操作者停止进程或证明进程已经停止。

SQLite 使用 `Connection.backup()`，包含 WAL 中已经提交的记录，排除未提交事务。图片、JSON、队列与数据库之间没有跨文件事务，因此备份仍要求停写。工具会比较源文件前后 SHA-256 和目录清单，发现变化就拒绝完成；这不能代替业务停写，也不防御具有相同本地写权限的恶意进程。

数据根必须准确指向业务数据目录。整个目录内的账号库、项目、图片、积分账本、队列、日志和私有材料都会保留；不会主动收集数据根之外的 Codex 登录、SSH 私钥、部署令牌或服务配置。外部配置和执行器持久缓存有单独的恢复需求，应在对应环境另行备份与演练。

## Windows 示例

下列路径是占位示例，不代表已操作真实 `data/`。目标父目录必须已存在。备份和恢复目标必须是全新目录，不能与源目录相同、互相嵌套，也不会覆盖已有目录。

```powershell
# 已停止示例数据根的全部写入后执行。
.\.venv\Scripts\python.exe -X utf8 .\scripts\backup_workbench.py backup `
  --data-root "D:\ExampleWorkbench\data" `
  --destination "D:\PrivateBackups\backup-20261013" --writers-stopped

.\.venv\Scripts\python.exe -X utf8 .\scripts\backup_workbench.py verify `
  --backup "D:\PrivateBackups\backup-20261013"

.\.venv\Scripts\python.exe -X utf8 .\scripts\backup_workbench.py restore `
  --backup "D:\PrivateBackups\backup-20261013" `
  --destination "D:\PrivateBackups\restore-check-20261013"
```

Linux 采用相同命令参数，把解释器替换为 `python3`。该工具没有替换线上数据根的命令。

### Windows 长路径

命令仍接收普通 Windows 路径；工具会先规范化路径，再统一使用扩展绝对路径访问源文件、目录、清单、备份和恢复副本。无需开启全局长路径开关，也无需缩短目标目录来绕过 260 字符边界。支持盘符路径及 UNC 路径的规范化；设备命名空间、残缺 UNC、ADS、含歧义尾点/尾空格的组件仍被拒绝。

SQLite 使用单独编码的只读 URI，避免扩展前缀被 `Path.as_uri()` 解释成无效 authority；WAL 快照、数据库完整性和只读保护保持。清单继续保存原相对路径，不写入 Windows 扩展前缀，仍可在 Linux 验证与恢复。

本机合成数据已实际验证 520 字符文件和 511 字符目录的完整往返。操作系统的单组件长度、总路径长度和实际文件系统限制仍然存在；UNC 只做了词法边界测试，没有访问网络共享。其他程序能否直接打开恢复出的长路径，需由对应程序另行验证。

## 校验和故障行为

备份包含 `manifest.json` 和 `data/`。清单记录相对路径、文件大小、SHA-256、SQLite 分类和空目录，不记录原机器的绝对路径。验证核对完整文件集合，拒绝额外、缺失、损坏或不匹配的文件；数据库执行 `integrity_check` 与 `foreign_key_check`。SQLite 的 `-wal`、`-shm`、`-journal` 不作为普通文件恢复，因为内容已合入独立快照。无法关联数据库的日志文件会导致备份中止。

路径检查拒绝符号链接、Windows junction/重解析点、路径穿越、ADS 和大小写冲突。源/目标不重叠同时检查规范路径与祖先目录的物理身份，Windows 8.3 短名不能绕过。创建目标使用独占方式；恢复前先完整验证备份，复制中再次检查哈希，恢复完成前再核对副本。

中断、磁盘失败或源数据变化会留下带 `.incomplete` 标记的私有目录，工具拒绝把它当成可用备份或后续备份源。不要删除标记冒充完成，也不要把该目录配置给服务。保留必要故障证据后，仅清理本次失败创建的目录，再使用另一个全新目标重试。工具不自动删除副本、旧备份或真实数据。

CLI 成功返回 0，输出只包含文件数、字节数、数据库数及验证状态；失败返回 1，输出错误类别和通用诊断，不输出凭据、SQL、源绝对路径或私有文件名。程序内部的 Python 接口保留具体异常，供受信任的本地调试使用。

## 私有数据边界

备份含密码哈希、会话记录、可能尚未使用的启用凭据、提示词及私有图片，属于敏感材料。Windows 在创建新容器时直接设置禁止继承的 DACL，仅当前用户、SYSTEM 和本机 Administrators 可访问；失败就中止。POSIX 创建新容器为 `0700`、复制文件为 `0600`。这些操作只作用于新输出，不改原数据或已有父目录权限。

工具不加密、不签名；SHA-256 检测意外损坏，不能证明来源可信。不要公开分享清单或副本，不要放进会公开发布或同步给他人的路径。移动到其他介质或机器后应重新核对访问控制及校验，并另用已批准的加密存储方案。能管理本机的管理员仍然属于信任边界。

恢复保留账号、密码哈希、会话和队列，便于一致性核对；不自动撤销会话或修改权限。因此副本只能用于隔离核对，不能公开启动为第二套生产服务。需要真实替换时，应另行批准目标、备份时间点、任务/回传状态与停机步骤。

## 本地验收与发布边界

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_backup_workbench.py -v
.\.venv\Scripts\python.exe -X utf8 .\work\iterations\R08\rehearse.py
.\.venv\Scripts\python.exe -X utf8 .\work\iterations\R08\long_path_rehearse.py
```

演练脚本只创建系统临时目录中的合成数据，检查实际 CLI 备份、校验、恢复、损坏拒绝和覆盖拒绝，结束后清理本次临时副本；不会读取真实数据。业务集成测试另外核对账号、归属、余额、账本、稳定 ID 和图片字节。当前结果见 [R08 检查记录](../work/iterations/R08/review.md)。

Windows 长路径问题的复现、修复与新增边界检查见 [长路径补充记录](../work/iterations/R08/long-path-review.md)。已失败的备份必须保留 `.incomplete`，修复后也应另选全新目标重试，不能继续写入或覆盖原失败副本。

首次真实发布还须核对对应服务器上的运行用户、数据根和权限、域名与 HTTPS、实际依赖安装、服务重启与健康状态、执行器令牌与回传、真实备份保存位置及隔离恢复。这些检查必须在获得相应环境和授权后进行。本地测试及模拟 systemd 不能证明云端生产已经可用。
