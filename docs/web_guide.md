# 本地网页使用手册

网页名称：**Image Workbench — 图片生成与修改工作台**。

这是个人本机工作台，默认只监听 `127.0.0.1`。项目、任务、原图、候选图和历史版本仍保存在原来的 `data/`；无需迁移旧数据。第四阶段网页已完成无额度演练，网页入口的一次真实生成和一次历史图编辑留给你手动验收。

## 启动

在项目根目录 `D:\ChatGPT\图片网站` 打开 PowerShell：

```powershell
# 首次安装；本次开发环境已经安装完成
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt

# 日常启动。启动网页本身不会发起生图
.\.venv\Scripts\python.exe -X utf8 -m image_workbench web
```

用 Chrome、Edge 等桌面浏览器打开 **http://127.0.0.1:7860**。默认后端为本地 Codex，使用原有登录和受限执行链；未增加付费 API，也未修改全局认证。比例选项通过提示词约束，实际图片尺寸以返回结果为准。

自定义数据目录或端口：

```powershell
.\.venv\Scripts\python.exe -m image_workbench --data-root "D:\我的图片工作台数据" web --port 7860
```

数据目录参数应放在 `web` 前面。不要启动热重载。只有 Worker 处理已提交队列；FastAPI 请求返回后，浏览器不必保持打开。关闭网页服务器的终端不会主动停止独立 Worker；已经明确提交的任务继续处理。再次启动同一数据目录会复用 Worker。未保存的表单草稿不保证在关闭页面后保留。

## 日常操作

1. 点击左侧 **新建项目**，填写中文名称。窄窗口点击顶部“项目与历史任务”展开入口。
2. 在“创作需求”中填写要求，选择生成或修改、画面比例。参考图支持 PNG、JPEG、WEBP，单张最多20 MiB、最多8张、总计40 MiB；后端检查实际内容及像素数。
3. 点击 **保存任务**。这一步只保存记录和参考图，不调用模型。
4. 在任务详情点击 **开始生成**。同一任务重复点击不会创建第二个生成作业。多个任务按提交顺序执行，一次只处理一个。
5. 查看等待执行、生成中、检查产物等状态。执行中的任务约每3秒刷新，只显示已用时间，不推测剩余时间。
6. 成功图片标记为 **等待审核**。点击图片看大图，点击 **下载** 获取原始输出；核对尺寸、格式、来源和内容后，点击 **确认通过**。审核结果保存到磁盘。
7. 点击任意历史任务的结果图旁 **基于此图继续修改**，填写修改意见，再依次保存、开始生成。可以从较早的 V1 或其他版本分支；原图片始终保留。

修改模式必须从已登记输出图选择基底；额外参考图可选。每次修改创建新任务和新图片 ID。生成成功只表示图片已校验、登记，不等于视觉质量已经人工通过。

## 无额度演练

使用独立数据目录，已有图片只作为演练输出复制，不调用 Codex：

```powershell
.\.venv\Scripts\python.exe -m image_workbench --data-root reports/web-preview/data web --backend local --image tests/manual_batch_cases/assets/fragrance.webp --port 7861
```

打开 http://127.0.0.1:7861，顶部显示“演练模式 · 不消耗生图额度”，按钮为“开始演练”。演练输出不会按提示词改变画面，它用于验证保存、执行、版本、审核和下载流程。不要将演练 Worker 与真实 Worker 指向同一数据目录。

## 一次真实生成的人工验收

本次开发未代你点击以下真实执行步骤。

1. 启动默认 `web`，确认顶部显示“本地 Codex · 手动启动”“执行器已运行”。
2. 创建“网页真实验收”项目，可上传一张自有参考图；输入“生成一张浅灰背景上的白色陶瓷杯产品照片，柔和自然光”，选1:1，保存。
3. 记下任务 ID，确认当前状态“待开始”。由你点击一次 **开始生成**。
4. 生成中刷新页面或关闭后重新打开，应读取同一任务，不新增执行。等待结果，检查图像可打开、格式/尺寸正确、执行记录仅一次。
5. 下载并打开原图，检查视觉内容，手动 **确认通过**。刷新后仍应为已通过。

## 一次历史版本编辑的人工验收

1. 选择上一步 V1 的任务结果（也可以选择原有历史输出）。点击 **基于此图继续修改**。
2. 输入“保持杯子的形状和机位不变，仅将背景改成浅蓝色”，保存新任务；核对“基底图片”为所选 V1。
3. 由你点击一次 **开始生成**，等待新候选图 V2。检查内容是否符合修改要求、来源 ID 是否等于 V1 的图片 ID。
4. 返回 V1，确认原图片和审核记录仍可读取。下载 V2，对比两张图后再决定确认通过或继续修改。

如果有问题，保留失败任务，按错误说明处理；不要自动连续重试。以上两项未完成前，应记录为“网页真实端到端待人工验收”，不能用演练结果替代。

## 失败与恢复

- **执行失败**：显示脱敏摘要；不会自动再次生图。修复原因后，点击“重试生成”才会提交一次新的请求。
- **登记失败**且存在候选文件：优先点击“恢复归档结果”，只校验和登记原候选文件，不重新生图。恢复仍由队列处理。
- **状态待确认**：可能是 Worker 或机器异常中断，旧子进程是否仍在工作未知。队列暂停，不自动重放任务。先检查本地进程和日志，确认旧执行已停止；再使用下面的本地命令解除。命令本身不终止进程，之后仍需你手动重试。

```powershell
.\.venv\Scripts\python.exe -m image_workbench worker-confirm-stopped --project <项目ID> --task <任务ID> --confirm-stopped
```

使用自定义数据目录时同样在子命令前传 `--data-root`。旧 CLI 活动记录没有网页作业时，使用原来的 `mark-interrupted --project ... --task ... --execution ...`，也必须先确认进程停止。

本地日志位置（不会通过网页下载接口暴露）：

- `data/projects/<项目ID>/tasks/<任务ID>/logs/runs/<执行ID>/`：原 TaskRunner 的执行记录、stdout、stderr、候选图片、计时。
- `data/.workbench/worker-process.log`、`worker-errors.log`、`web-errors.log`：网页与队列错误。
- `data/.workbench/worker.json`：Worker PID、后端和启动时间。需要完全退出时，先确保没有活动/排队任务，再关闭网页进程和这里对应的 Worker 进程。

如果页面提示校验失效，请刷新后继续；网页重启会更换页面校验令牌。若端口占用，可使用 `--port 7862`。程序没有提供任意路径读取、在线日志查看、删除项目或更改全局登录的网页入口。

## 验证与备份

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

自动化测试使用独立临时目录和本地测试图片，不调用真实 ImageGen。Windows 受限沙箱可能阻止 asyncio 创建本地回环套接字；在正常 PowerShell 本机环境运行即可，无需修改应用绑定地址或关闭安全设置。

备份/迁移前先停止网页与 Worker，复制**完整数据根目录**，包括隐藏的 `.workbench/` 和全部 `projects/`。审核记录和队列保存在 `.workbench/`，不能只复制图片。不要手动改图片或 JSON；文件哈希不匹配时网页拒绝预览、下载和通过审核。
